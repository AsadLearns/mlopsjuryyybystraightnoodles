1. Executive Summary & Objective

In modern production machine learning, deploying models into production requires addressing trade-offs between serialization format, runtime execution engines, and target hardware environments.

This project implements and evaluates an end-to-end MLOps pipeline for sentiment classification, serializing a single trained neural network into three industry-standard formats: Pickle (.pkl), PyTorch Native (.pt), and ONNX (.onnx). We benchmark across two core deployment targets: a lightweight Edge Deployment powered by ONNX Runtime and a Cloud-Style REST API built with FastAPI and packaged in a Docker container.

8. College Viva Jury Q&A Summary

Q1: Why is ONNX Runtime faster than PyTorch on CPU?
Answer: ONNX Runtime optimizes the computation graph beforehand (constant folding, operator fusion, and memory pre-allocation) and uses lightweight C++ kernels without Python runtime interpreter overhead.
Q2: Why not deploy with Pickle (.pkl)?
Answer: Security and portability. Pickle can execute arbitrary code during unpickling, making it an RCE attack vector. It also requires the exact same Python classes and environment.
Q3: What is the benefit of increasing Batch Size from 1 to 32?
Answer: Vectorization and hardware utilization. Larger batch sizes allow CPU SIMD registers to process multiple sentences simultaneously, boosting throughput from 18,300 to over 390,000 samples/sec.
Q4: How did you handle Docker containerization?
Answer: We authored a production-ready multi-stage Dockerfile using python:3.11-slim, configured port mapping (-p 8000:8000), and implemented automated health checks. In production enterprise MLOps, images are built on remote Linux CI/CD pipelines (e.g. AWS ECS / Cloud Run) rather than local laptops.
